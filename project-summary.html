💻 สถาปัตยกรรมฝั่ง Client (Dashboard) Zero-Build

สร้างด้วย Pure ES Modules (Vanilla JS + Modern CSS) ไม่ต้องผ่านขั้นตอนการ Build ที่ซับซ้อน โหลดเร็วระดับมิลลิวินาที มีระบบตรวจจับการเปลี่ยนวันอัตโนมัติเมื่อเที่ยงคืน (Midnight Rollover) พร้อม Drawer สำหรับผู้ดูแลระบบที่ล็อกด้วย ADMIN_TOKEN

  • คำนวณวันคงเหลือสดในเบราว์เซอร์จากวันที่สิ้นสุดจริง
  • ค้นหาแบบ Instant Search ครอบคลุมทุกฟิลด์ (ชื่อ, ตำแหน่ง, หมู่บ้าน, ตำบล, เบอร์โทร)
  • สลับมุมมองและกรองสถานะ (ดำรงวาระ, ใกล้หมดวาระ, หมดวาระแล้ว, ข้อมูลไม่สมบูรณ์)
⚙️ สถาปัตยกรรมฝั่ง Server (Engine) Zero-Dependency

รันบน Node.js Native Modules (node:net, node:tls, node:crypto, node:sqlite) ไม่มี Dependency ภายนอกที่ไม่จำเป็น ทำให้มีความเสถียรสูง ปลอดภัยจาก Supply Chain Attack และเบามาก

  • รองรับทั้งโหมด Local Server (Dev) และ Serverless Functions บน Vercel (Production)
  • ระบบป้องกันการส่งซ้ำระดับ Database (Idempotent Notification Key)
  • บันทึกประวัติการส่งอีเมลแบบ Deterministic Snapshot และ Audit Log ครบถ้วน

วิธีการคำนวณและประมวลผลข้อมูล (Calculation Logic)

1

อ่านและแปลงข้อความวาระภาษาไทย (Parse Duration)

ระบบรับชุดข้อมูลต้นทางซึ่งระบุวาระในรูปแบบข้อความไทย เช่น "5 ปี 1 เดือน", "0 ปี 2 เดือน", "3 เดือน 15 วัน" หรือตัวเลขไทย (๑-๙) จากนั้นฟังก์ชัน parseDurationWara() จะแปลงเป็นโครงสร้างข้อมูลระยะเวลา { years, months, days }

2

หา "วันที่สิ้นสุดวาระที่แท้จริง" (Calculate Term End Date)

นำระยะเวลาที่แปลงได้ไปบวกเข้ากับ วันที่อ้างอิงข้อมูล (Reference Date) โดยใช้คณิตศาสตร์ปฏิทินแบบ Calendar-Accurate (รองรับปีอธิกสุรทินและการปัดวันเกินเดือนอย่างถูกต้อง): 

วันที่สิ้นสุดวาระ (Term End Date) = วันที่อ้างอิงข้อมูล (Reference Date) + ระยะเวลาวาระคงเหลือ
3

คำนวณ "วันคงเหลือแบบเรียลไทม์" (Live Days Left)

คำนวณความต่างของวันระหว่าง "วันที่สิ้นสุดวาระ" กับ "วันที่ปัจจุบันในเวลาประเทศไทย (Asia/Bangkok UTC+7)" โดยใช้ Date.UTC เพื่อป้องกันความคลาดเคลื่อนจากเขตเวลาหรือการปรับเวลา: 

วันคงเหลือ (Days Left) = วันที่สิ้นสุดวาระ − วันนี้ (Asia/Bangkok)
4

การจำแนกสถานะ 4 ระดับ (Status Classification)

สถานะ เงื่อนไขทางคณิตศาสตร์ ความหมายและการแสดงผล
🟢 ดำรงวาระ (Active) วันคงเหลือ > เกณฑ์ (เช่น > 30 วัน) ยังอยู่ในวาระปกติ ไม่ต้องดำเนินการเร่งด่วน
🟡 ใกล้หมดวาระ (Expiring Soon) 0 ≤ วันคงเหลือ ≤ เกณฑ์ (รวมถึงวันสิ้นสุดพอดี 0 วัน) ต้องเตรียมกระบวนการสรรหา / เลือกตั้ง / ส่งมอบงาน
🔴 หมดวาระแล้ว (Expired) วันคงเหลือ < 0 สิ้นสุดการดำรงตำแหน่งแล้ว
⚪ ข้อมูลไม่สมบูรณ์ (Invalid) ข้อมูลวาระว่าง / รูปแบบวันที่ไม่ถูกต้อง แสดงสัญลักษณ์ ⚠ และระบุสาเหตุข้อผิดพลาด ไม่ถูกนำไปคำนวณสถิติ

ระบบแจ้งเตือนอัตโนมัติ (Automated Notification System)

ระบบขับเคลื่อนการแจ้งเตือนถูกออกแบบให้ส่งอีเมลอย่างตรงจุดตามวงรอบเวลาที่กำหนด พร้อมดีไซน์เทมเพลตมาตรฐานราชการ (Government Official Format)

1. เตือนล่วงหน้า 6 เดือน 6-Month

ชนิด: six_month
เกณฑ์: วาระเหลือ ≤ 6 เดือน (180 วัน)
ผู้รับ: เจ้าหน้าที่รายบุคคล + สำเนาผู้บริหาร/ทีมงานอำเภอ
วัตถุประสงค์: แจ้งเตือนล่วงหน้าเพื่อเตรียมการวางแผนงบประมาณ การตรวจสอบคุณสมบัติ และกระบวนการสรรหาหรือเลือกตั้งใหม่ 

หัวข้อ: รายงานวาระการดำรงตำแหน่ง 2569: [ชื่อบุคคล]
2. เตือนล่วงหน้า 1 เดือน 1-Month

ชนิด: one_month
เกณฑ์: วาระเหลือ ≤ 1 เดือน / ≤ 30 วัน (และวันหมดวาระพอดี)
ผู้รับ: เจ้าหน้าที่รายบุคคล + สำเนาผู้บริหาร/ทีมงานอำเภอ
วัตถุประสงค์: แจ้งเตือนขั้นวิกฤต เตรียมส่งมอบภารกิจและอุปกรณ์ทางราชการ และประกาศรับสมัครผู้มีสิทธิเข้ารับการคัดเลือก 

หัวข้อ: รายงานวาระการดำรงตำแหน่ง 2569: [ชื่อบุคคล]
3. สรุปรายงานประจำปี Annual Summary

ชนิด: annual_summary
เกณฑ์: รันทุกวันที่ 31 ธ.ค. หรือเวลา 09:00 น.
ผู้รับ: ผู้บริหาร / นายอำเภอ / ทีมงานปกครอง
วัตถุประสงค์: รายงานภาพรวมสถิติเจ้าหน้าที่ทั้งหมดที่จะครบวาระในปีนั้น พร้อมตารางรายชื่อแยกตามตำบล/หมู่บ้าน 

หัวข้อ: สรุปข้อมูลการหมดวาระประจำปี 2569
🛡️ กลไกป้องกันการส่งซ้ำและการจัดการความผิดพลาด (Deduplication & Retry) Enterprise Grade

1. Unique Notification Key

สร้างคีย์เฉพาะ ${type}:${personId}:${termEndDate} ฝังเป็น Unique Constraint ในฐานข้อมูล ทำให้ไม่ว่าคำสั่ง Cron จะรันกี่รอบ ก็จะไม่มีทางส่งอีเมลซ้ำให้บุคคลเดิมในวาระเดิมเด็ดขาด

2. Atomic State Claiming

ก่อนเริ่มส่งเมล ระบบจะทำการเปลี่ยนสถานะจาก pending เป็น sending ทันที เพื่อป้องกันกรณีที่มี Worker รันคู่ขนานกันพร้อมกัน (Race Condition)

ระบบส่งอีเมล (Native SMTP Client & Security)

🚀 จุดเด่นของ Native SMTP Client Custom Built

พัฒนาขึ้นด้วย node:net และ node:tls โดยตรง ไม่ต้องติดตั้งแพ็กเกจภายนอกอย่าง Nodemailer ทำให้ประหยัดทรัพยากรและลดความเสี่ยงด้านความปลอดภัย

  • รองรับทั้งพอร์ต 465 (Implicit TLS) และ 587/25 (STARTTLS)
  • ระบบเข้ารหัสภาษาไทย RFC 2047 Word Wrapping ป้องกันชื่อภาษาไทยเพี้ยน
  • มี Timeout ทุกคำสั่ง ป้องกัน Socket ค้างตลอดไป
  • รองรับเทคนิค MIME Multipart ทั้ง HTML สวยงามและ Plain-text สำหรับโปรแกรมรุ่นเก่า
🛡️ มาตรฐานความเข้ากันได้ Microsoft 365 M365 Verified

ผ่านการปรับแต่งเพื่อให้ส่งเข้า Microsoft 365 Group Mailbox (เช่น dopa-only-tm@forth.co.th) ได้อย่างราบรื่นโดยไม่ถูก Anti-Spam กรองทิ้ง

  • ใส่ Header Date: ตามมาตรฐาน RFC 5322 อย่างเคร่งครัด
  • ละเว้น Header ที่ทำให้ M365 ตีความเป็น System Bot เช่น Auto-Submitted
  • ใช้โครงสร้างตาราง HTML แบบทางการที่ผ่านตัวกรองความปลอดภัยระดับองค์กร
  • ไม่ส่งรหัสผ่าน SMTP_PASS ออกมายังเบราว์เซอร์เด็ดขาด
