สรุปภาพรวมผู้บริหาร (Executive Summary)

ระบบการส่งอีเมลและตั้งค่า SMTP ของแอปพลิเคชัน StockFlow ได้ถูกออกแบบและใช้งานจริงแบบ Hybrid Architecture โดยรวมเอาส่วนประสานงานผู้ใช้ (React Client) เข้ากับบริการฐานข้อมูล Supabase PostgreSQL (สำหรับจัดเก็บระบบ Vault ของรหัสผ่านและค่าคอนฟิก) และฟังก์ชัน Serverless Vercel Endpoint (Node.js + Nodemailer) สำหรับทำหน้าที่เป็น Mail Transport

✔ จุดเด่นที่ได้รับการตรวจสอบว่าใช้งานจริง
  • มีหน้าจอตั้งค่า SMTP พร้อมรองรับ Secure Password Vault (`system_secrets` table)
  • การเก็บรหัสผ่านแยกจากค่าคอนฟิกทั่วไป ไม่ส่งรหัสผ่าน Plaintext กลับมายัง Frontend
  • มีปุ่มและ Modal สำหรับทดสอบส่งอีเมล (Test Email) พร้อมระบบ Override คอนฟิกแบบเรียลไทม์
  • มี Graceful Fallback ไปยัง Supabase Native Auth เมื่อ Vercel Endpoint ออฟไลน์
  • รองรับสิทธิ์ `settings.update` ในการบันทึกข้อมูล พร้อมระบบ Audit Log ทุกธุรกรรม
⚠️ ประเด็นข้อจำกัดที่พบใน Codebase
  • ปุ่ม/ตัวเลือก "Verify TLS Certificate" ใน UI ไม่ได้ถูกส่งไปใช้งานจริงใน Backend Vercel Endpoint (`api/send-email.js` ฮาร์ดโค้ด `rejectUnauthorized: false`)
  • ใน `api/send-email.js` มีการฮาร์ดโค้ดรหัสผ่าน fallback plain-text ในซอร์สโค้ด (Line 31)
  • `api/send-email.js` ตั้งค่า CORS แบบเปิดกว้าง (`Access-Control-Allow-Origin: '*'`) โดยไม่มีการยืนยัน Authenticated Bearer Token ใน HTTP Body

2. SMTP Backend Implementation

การวิเคราะห์ฟังก์ชันเบื้องหลัง (Trace Source Code)

การทำงานของระบบ SMTP Backend ถูกแบ่งออกเป็น 2 ชั้นสถาปัตยกรรม (Database Serverless Vault & Vercel API Service):

1. PostgreSQL System Settings & Vault (Supabase)
  • Config Loader: admin_get_system_settings() (Migration 11) รวบรวมค่าจากตาราง system_settings
  • Config Saver: admin_update_system_settings() (Migration 11) บันทึกค่า JSONB โดยยกเว้นรหัสผ่าน plain-text
  • Password Vault: admin_update_smtp_password() (Migration 14 & 32) บันทึกรหัสผ่านในตาราง system_secrets
  • Password Retrieval: admin_get_smtp_password_internal() (Migration 14 & 31) ถูกจำกัดการเรียกใช้เฉพาะ service_role
2. Mail Transporter (Vercel Serverless Function)
  • Endpoint File: api/send-email.js
  • Transporter Setup: nodemailer.createTransport() (Line 34)
  • Authentication: auth: { user, pass } (Line 38-41)
  • Port & TLS Handling: secure: port === 465 (Line 37)
  • Execution: transporter.sendMail(mailOptions) (Line 55)

ลำดับขั้นตอนการส่งอีเมลปกติ (Standard Email Flow)

1
Trigger Notification Event
ระบบเกิดเหตุการณ์ (เช่น อนุมัติการเบิกจ่าย) หรือเรียกใช้ sendStockFlowEmail() จาก emailService.js

3

emailService.js ยิง HTTP POST ไปยัง /api/send-email พร้อม Payload { to, subject, html, text }
4
Nodemailer Transporter Processing
api/send-email.js อ่านค่า SMTP Config (จาก Overrides หรือ Environment Variables) และเชื่อมต่อไปยัง SMTP Server
5
SMTP Transmission & Fallback
หากส่งผ่าน Vercel API สำเร็จจะคืนค่า messageId; หาก Vercel API ล้มเหลว จะสลับไปใช้ Supabase Native Auth Fallback

1
Click "Test Email" & Input Recipient
ผู้ใช้กดปุ่มในหน้า Settings และระบุอีเมลปลายทางใน Modal (src/pages/Settings.jsx:996)

Construct SMTP Overrides Payload

3
Execute sendTestEmail()
เรียก sendTestEmail(trimmedEmail, null, customSmtpOverrides) ใน emailService.js ซึ่งสร้าง HTML ทดสอบด้วย renderTestEmailHtml()
4
Direct Override Dispatch
api/send-email.js ได้รับ smtpOverrides และใช้อัปเดต Transporter ชั่วคราวโดยตรงโดยไม่ต้องบันทึกลงฐานข้อมูลก่อน
5
Feedback & Toast Notification
แสดง toast.success("ส่งอีเมลทดสอบสำเร็จ") หรือ toast.error() แจ้งข้อผิดพลาดให้ผู้ใช้ทราบทันที

6. SMTP Protocol Behavior

พฤติกรรมการเชื่อมต่อระดับโปรโตคอลตามค่าคอนฟิกที่ระบุ:

Implicit TLS (Port 465)

เมื่อตั้งค่า port = 465 และ secure = true: Nodemailer จะทำการเริ่มการเชื่อมต่อผ่าน SSL/TLS Socket ทันทีตั้งแต่ TCP Handshake แรกกับ SMTP Server เหมาะสำหรับ Gmail และเซิร์ฟเวอร์ยี่ห้อมาตรฐาน

Explicit TLS / STARTTLS (Port 587 / 25)

เมื่อตั้งค่า port = 587 (หรือ 25) และ secure = false: Nodemailer จะเชื่อมต่อในลักษณะ Plaintext TCP Socket ก่อน แล้วส่งคำสั่ง STARTTLS เพื่อยกระดับความปลอดภัยเป็น SSL/TLS ก่อนเริ่มส่งข้อความ

⚠️
คำเตือนเรื่องการสับสนพอร์ตและโปรโตคอล (Port Mismatch Banners in UI):
• หากเลือก Port 465 แต่เลือก STARTTLS (secure: false) อาจเกิดข้อผิดพลาด Socket Timeout (ETIMEDOUT)
• หากเลือก Port 587 แต่เลือก Implicit TLS (secure: true) อาจเกิดข้อผิดพลาด "Greeting never received"

7. Email Service & Renderer Module

โมดูล src/lib/emailService.js & src/lib/emailRenderer.js

ซอร์สโค้ดฝั่ง Client มีฟังก์ชันหลัก 3 ฟังก์ชันสำหรับประมวลผลและส่งอีเมล:

  • sendStockFlowEmail({ to, subject, html, text, smtpOverrides, actionUrl }) — ฟังก์ชันแกนหลักที่ทำหน้าที่ส่ง HTTP POST ไปยัง /api/send-email และตัดสลับไปใช้ Supabase Native Auth เมื่อมีข้อผิดพลาด
  • sendTestEmail(toEmail, eventType, smtpOverrides) — ฟังก์ชันส่งอีเมลทดสอบจากหน้าตั้งค่า โดยเรียกใช้แม่แบบ renderTestEmailHtml()
  • sendUserInvitationEmail({...}) — ฟังก์ชันส่งอีเมลคำเชิญผู้ใช้งานใหม่ พร้อมแม่แบบ HTML เฉพาะสำหรับต้อนรับสมาชิกใหม่
  • renderEmailHtml({ branding, template, data }) — ตัวสร้างโครงสร้าง HTML แบบ Inline Style ที่รองรับการแสดงผลบน Microsoft Outlook และ Gmail พร้อมแสดงรายการตารางวัสดุเบิกจ่าย

9. Database / Data Model Schema

ผังตารางฐานข้อมูล Supabase PostgreSQL (Schema Definitions)

11_system_settings.sql & 14_smtp_password_vault.sql
-- 1. ตารางเก็บค่าคอนฟิกทั่วไปของระบบ
CREATE TABLE IF NOT EXISTS public.system_settings (
  key TEXT PRIMARY KEY,
  value JSONB NOT NULL,
  category TEXT NOT NULL DEFAULT 'general',
  description TEXT,
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  updated_by UUID REFERENCES public.profiles(id)
);

-- 2. ตารางเก็บค่าความลับ Vault (รวมรหัสผ่าน SMTP)
CREATE TABLE IF NOT EXISTS public.system_secrets (
  key TEXT PRIMARY KEY,
  secret_value TEXT NOT NULL,
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  updated_by UUID REFERENCES public.profiles(id)
);

-- 3. ตารางประวัติ Audit Log การแก้ไขการตั้งค่า
CREATE TABLE IF NOT EXISTS public.audit_logs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  actor_id UUID REFERENCES public.profiles(id),
  action TEXT NOT NULL,
  details JSONB,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

13. Known Issues & Security Audit Audit

🚫
1. Discrepancy in TLS Certificate Validation:
ใน UI src/pages/Settings.jsx มี Checkbox ให้ผู้ใช้เลือกเปิด/ปิดการตรวจใบรับรอง (reject_unauthorized) แต่ในไฟล์ api/send-email.js กลับเขียนค่าคงที่เป็น tls: { rejectUnauthorized: false } ส่งผลให้การตั้งค่าจากหน้าจอไม่มีผลต่อการเชื่อมต่อจริงใน Backend
⚠️
2. Plaintext Hardcoded Password Fallback in API Code:
ในไฟล์ api/send-email.js บรรทัดที่ 31 มีการใส่รหัสผ่านแอป (App Password) แบบ plain-text สำรองไว้ในซอร์สโค้ด ซึ่งเสี่ยงต่อการหลุดของข้อมูลหาก Repo ถูกเข้าถึง
ℹ️
3. Open CORS Wildcard on API Route:
เส้นทาง /api/send-email กำหนดค่า Access-Control-Allow-Origin: '*' และไม่บังคับส่ง Auth Token ซึ่งอาจถูกผู้อื่นส่ง HTTP Request เพื่อใช้เซิร์ฟเวอร์ SMTP ยิงอีเมลสแปมได้

15. Conclusion & Recommendations

ข้อเสนอแนะในการปรับปรุง (Actionable Recommendations)

  1. เชื่อมโยงตัวเลือก TLS Certificate Verification: ปรับปรุงไฟล์ api/send-email.js ให้รับค่า smtpOverrides.reject_unauthorized หรืออ่านจากระบบการตั้งค่า เพื่อให้สวิตช์ใน UI มีผลทำงานจริง
  2. ลบรหัสผ่าน Plaintext Fallback ออกจากซอร์สโค้ด: ลบสตริงรหัสผ่านสำรองในบรรทัด 31 ของ api/send-email.js และเปลี่ยนไปใช้การอ่านจาก Environment Variable หรือ Supabase Vault ผ่าน Service Role RPC เท่านั้น
  3. เพิ่มการยึดสิทธิ์ API Route (Protect API Route): เพิ่มการตรวจสอบ Supabase Authorization Header หรือ Secret Key ระหว่าง Client และ Vercel Endpoint เพื่อป้องกันการเรียกใช้งาน /api/send-email จากภายนอก
  4. สร้างตารางประวัติการส่งอีเมล (Email Audit Log): เพิ่มตารางสำหรับจัดเก็บประวัติการส่งข้อความแจ้งเตือน (Status, Recipient, Sent At, Error Log) เพื่อการตรวจสอบย้อนหลัง
